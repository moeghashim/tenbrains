# Ten Brains backend — scope

Goal: replace scripted demo data with a real Wayfinder backend while preserving the product's core invariant — **Wayfinder never silently mutates the map; every change stages for Your review**.

## Architecture

- **Server**: small Node 22 service in `app/server/` (Express), run alongside Vite. Dev port 5174; Vite proxies `/api` to it.
- **State**: in-memory store with JSON-file persistence (`app/server/data/`), one document per discovery: map (Destination, Open Frontier, Fog of War, Closed Decisions), sessions, transcripts, evidence, staged candidates. No database until the data model settles.
- **Provider adapter**: one interface, two implementations.
  - `MockProvider` (default, no key needed): deterministic streaming replies derived from the user's input; always produces reviewable staged candidates. Keeps the full loop testable and free.
  - `AnthropicProvider` (enabled when `ANTHROPIC_API_KEY` is set): Claude (`claude-sonnet-5`) with a system prompt encoding the two-actor model, voice.md rules, and a structured tool contract — Wayfinder returns staged candidates as typed JSON (destination-draft | ticket | fog-question | closed-decision), never map writes.
- **Streaming**: SSE events `token`, `candidate`, `done`, `error` so the UI can render the reply and the staging panel live.

## API (phase 1 surface)

- `POST /api/discoveries` — create a discovery
- `GET  /api/discoveries/:id` — full state (map + staged)
- `POST /api/discoveries/:id/intake/messages` — user turn → SSE stream of Wayfinder turn + staged candidates
- `POST /api/discoveries/:id/intake/approve` — apply the selected staged items to the map (the ONLY endpoint that mutates the map)

## Phases

1. **Intake live (mock)** — server + store + mock provider; wire the `/discoveries/new` chat and its staged panel + approve flow to the API. Demo routes stay untouched (`?demo=1` keeps working).
2. **Real model** — AnthropicProvider behind the env key; prompt + tool contract; provider selected at runtime.
3. **Grilling session live** — session objective/line-of-inquiry context, evidence capture, candidate updates through the same staging contract; Session map reads real session data.
4. **Map persistence + discoveries list** — real multi-discovery CRUD; landing state driven by the store.

## Non-goals (for now)

- Auth/multi-user (single local user), deployment, database, real-time collaboration — the two-actor model makes most of this unnecessary by design.

## Invariants (all phases)

- Two actors only: You, Wayfinder, You + Wayfinder.
- Map mutation only via explicit approve.
- Copy generated by Wayfinder follows voice.md (encoded in the system prompt).
- Node 22; build must stay green at every phase.
